# Routine availability and rental progression

Approved October 12, 2026. Check requested availability, Proceed to rent, and selecting Existing/New/Uncertain customer type are routine actions qualified by the current workflow. They advance directly without asking the worker for verification evidence or an additional confirmation dialog.

Checking availability still validates the request and reevaluates equipment. Proceeding still applies the temporary-allocation rules and only advances to customer identification after a successful allocation. Invalid requests, blocked equipment, conflicts, and authority restrictions remain enforced.

The existing domain command record receives a clearly labeled UI interaction reference for these routine actions, not invented inspection, approval, or customer verification evidence. Staff approval and qualified resolution actions retain their explicit evidence prompts. This change supersedes the earlier blanket action-dialog presentation for these routine controls.

Browser validation checks availability/rental progression and all three customer type choices produce no dialog, protection is recorded before intake, and staff approval still requires evidence. Existing rental and role checks remain covered.

Customer type selection routes the workflow; it does not verify identity, profile, billing, or insurance. Those verification fields retain their evidence prompt, and an Uncertain match still blocks acceptance.
